## Риски

- **Незапиннутый `ruff`** (`>=0.6,<1`): новая версия включает новые правила по умолчанию — CI ломается без изменений в коде.
- **416 → 503:** любая страница за последней (и `page>1` на пустой БД) выглядит как сбой сервиса; на пустом проде это основной сценарий.
- **Локальная сеть блэкхолит TCP-диапазоны Supabase** (`8.47.69.0/24`, `8.6.112.0/24`): локальные live-e2e невозможны, проверка — через Management API и прод. Обход: VPN/прокси. Также локально нестабилен TLS до `*.vercel.app` — live-проверки делать через внешний fetch.
- **Порядок миграции 013:** trigger блокирует публикацию без approved proof создателя. Новый код одобряет completion до публикации; старый код (если ещё жив на Vercel) делал наоборот. Поэтому 013 применяется только после деплоя новой версии.
- **Сброс пароля** рассчитан на implicit-flow Supabase (токены в `#access_token`). Если в проекте включат PKCE, страницу нужно доработать под `?code=`.
