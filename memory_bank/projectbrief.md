# Project Brief — Global Achievement List (GAL)

## Цель

Глобальная платформа для рейтинга человеческих достижений. Сравнение достижений из разных сфер (Geometry Dash, музыка, шахматы, программирование, Minecraft, образование, спорт) через единую относительную шкалу сложности, построенную на личных сравнениях пользователей.

> **Статус: MVP v1.0–v1.9 завершены и задеплоены.** Код v1.8 в `main` (`8f068e0`) задеплоен, hotfix `b1fa1cd` (лидерборд откатывается на legacy-выборку, пока нет колонок SE/CI); миграции 013–020, 022 (canonical ranking + порог 2 + CHECK ссылок), 023 (публичные списки прошедших), 024 (backfill ранга для 2 оценок), а также 025 (SE/CI Bradley–Terry), 026 (доказательства в публичных прохождениях) и 027 (топ-5) применены к проду (025/026/027 — 2026-11-14, HTTP 201). Значения SE/CI появятся после пересчёта BT на существующих данных. Не применена только 021 (OAuth-провайдер). Вход через LTHub и GAL как OAuth-провайдер, «Мои заявки», сложность при создании/прохождении, сравнительный выбор и живые оценки (новые заявки меняют топ). v1.9 добавляет предварительный топ-5: заявка автора → ручное решение модератора → временная позиция `#N*` в общем топе с переходом на третьей обычной оценке; постоянный BT-алгоритм не изменён. С 2026-11-17 независимая экспертиза топ-5 отключена, осталось только ручное выставление места модератором. v1.10 добавляет видимость доказательств: при отправке прохождения доказательство можно скрыть от других; публичные списки не показывают его, владелец и модераторы видят, верификацию создателя скрыть нельзя (миграция 028 применена к проду 2026-11-15, HTTP 201; по умолчанию доказательства видимы). UI оформлен в стиле VKUI (light/dark), ошибки Storage показываются пользователю понятным текстом. Создать своё достижение можно только после оценки опубликованного достижения (проверка в UI, сервисе и RLS). Публичные профили показывают очки, пройденные и созданные достижения; карточка достижения — место, BT-силу с ± SE и 95% ДИ, прошедших пользователей и отправку прохождения. Security: CSP/nosniff/HSTS, фильтрация схем ссылок, устойчивость сессии к сетевым сбоям. 2026-11-15 проведён сквозной баг-хант (D17): исправлены фоновый auto-refresh токенов, распознавание невалидной сессии, регистрация служебных email, Host-доверие в recover, не-ASCII state LTHub, wildcard в логине, смена пароля без обновления сессии, дробный `rank_order` в сортировках, фильтр постоянных мест в профиле, гонка очистки временного топа (миграция 030) и «дыра» в позиции оценки (миграция 029); контент/модерация проверены без новых находок. Миграции 029/030 к проду не применены. `pytest` — 298 passed, `ruff check`/`format` — чисто.

## Рамки v1.10 (D16) — видимость доказательств

- при отправке прохождения автор выбирает, показывать ли доказательство другим пользователям;
- скрытое доказательство не выводится в карточке достижения и публичном профиле (пустой список proofs в RPC);
- владелец прохождения и модераторы видят скрытые доказательства (проверка `auth.uid()`/`is_moderator()` в RPC, очередь модерации — напрямую под RLS);
- верификация создателя (прохождение собственного достижения) скрыта быть не может — триггер БД принудительно ставит `proofs_visible = true`;
- миграция 028 и обратная совместимость: до её применения код сохраняет доказательства видимыми и не ломает отправку.

## Рамки v1.9 (D15) — предварительный рейтинг топ-5

- заявка автора: достижение, предлагаемое место 1–5, доказательство и обоснование; одна активная заявка на достижение;
- решения модератора: `approved` (временная позиция с ручным местом 1–6), `rejected` с причиной, отмена и повторная проверка, журнал `top5_events`;
- независимая экспертиза временно отключена (2026-11-17): приглашения и отдельные голоса недоступны в UI и сервисе, legacy-голоса `expert` не учитываются; таблицы экспертных приглашений остаются в схеме 027 для совместимости;
- раздельное хранение обычных оценок и ручных решений модератора (без роста `evaluation_count`), запрет самоодобрения;
- временная сила `anchored_strength` против фиксированного постоянного топ-5, ручное место сравнивается только с соседними опорами (prior α=10);
- общий топ: `#3` постоянная и `#3*` временная позиции, временные могут занимать слоты и сдвигать других, но не делают чужие постоянные места временными;
- переход на третьей независимой обычной оценке: снятие временной записи, пересчёт постоянного BT и места;
- миграция 027 (таблицы, RLS, guard-триггеры, RPC, вьюха `public.public_achievements`) и тесты переходов 0/1/2/3.

## Рамки v1.2 (D13) — Bradley–Terry

- построение попарных сравнений из индивидуальных шкал (все пары, вес `1/(k-1)`);
- оценка глобальных сил регуляризованным MM-алгоритмом (prior κ=0.5, центрирование);
- колонки `bt_strength`, `bt_rating` (1000 + 400·s/ln10), `bt_comparisons`, `bt_updated_at`;
- ранжирование по `bt_strength desc` с fallback на среднюю позицию;
- атомарное применение через RPC `apply_bt_ratings(jsonb)` (service role) + advisory lock;
- автопересчёт после оценок, модерации и принятия жалоб; ручной `scripts/recompute_bt.py`;
- эксперимент точности/устойчивости (`scripts/bt_experiment.py`) и docs/bradley_terry.md.

## Рамки v1.8 (D14) — надёжность Bradley–Terry

- кластерный nonparametric bootstrap по личным шкалам пользователей (минимум 3 шкалы, 5 валидных реплик);
- SE и 95% percentile CI для BT-рейтинга с детерминированным seed и адаптивным числом реплик;
- хранение `bt_rating_se`, `bt_rating_ci_low`, `bt_rating_ci_high` (миграция 025) и защита полей guard-триггером;
- вывод «± SE» и доверительного интервала в карточке достижения и лидерборде; при недостатке данных интервал скрывается;
- тесты стабильности, краевых случаев и SQL/payload-контракта; документация методики и ограничений.

## Рамки MVP (v1.0)

Стек: Python + FastAPI + Jinja2 + Supabase (PostgreSQL + Auth + Storage) + Vercel.

MVP покрывает базовую цепочку:

```text
Achievement → Proof → Moderation → Evaluation → Global Rank → Player Score → Leaderboard
```

## Что НЕ входит в MVP

- AI-модерация;
- weighted average / опыт пользователя;
- reputation score;
- исторический график рейтинга;
- автоматическое определение дубликатов;
- социальная сеть / чаты;
- внутренние достижения сайта;
- интеграция API игр;
- мобильное приложение;
- статус Draft (только `pending → published`).

## Draft Decision (Draft отсутствует)

- User создаёт `pending` achievement
- Creator обязан приложить proof собственного выполнения
- Achievement публикуется только после модерации
- Creator автоматически становится первым выполнившим и первым evaluater-ом

## Success Criteria MVP

Пользователь способен полностью пройти цикл: регистрация → создание достижения → proof → модерация → публикация → выполнение другим пользователем → proof → модерация → личная оценка → попарные сравнения → глобальная сила Bradley–Terry → ранг → очки → player leaderboard.
