# Bradley–Terry ранкинг

Документ описывает, как GAL считает глобальную сложность достижений после перехода на модель Bradley–Terry (идея — [`idea.md`](idea.md)).

## 1. От личных шкал к попарным сравнениям

Пользователь оценивает только те достижения, которые сам подтверждённо выполнил, и размещает их в личной шкале: позиция `1` — самое сложное, дальше по возрастанию.

Для пользователя с `k` оценёнными достижениями, упорядоченными по позиции, строится `k(k-1)/2` сравнений: если `A` стоит выше `B`, то `A` считается сложнее `B`. Все пары одного пользователя зависимы (это одно упорядочение), поэтому каждая пара получает вес

```text
w = 1 / (k - 1)
```

так вклад пользователя растёт сублинейно с длиной шкалы и один «длинный» пользователь не подавляет остальных. Ничьи по позиции пропускаются.

## 2. Модель

Для достижений `i`, `j` с силами `s_i = ln θ_i`:

```text
P(i сложнее j) = σ(s_i - s_j) = θ_i / (θ_i + θ_j),   σ(x)=1/(1+e^-x)
```

Оценка — максимум взвешенного правдоподобия:

```text
L(s) = Σ_{i,j} w_ij [ y_ij ln σ(s_i-s_j) + (1-y_ij) ln σ(s_j-s_i) ]
```

Модель определена с точностью до сдвига, поэтому силы центрируются: `mean(s)=0`.

## 3. Регуляризованный MM-алгоритм

Используется minorization–maximization (Hunter, 2004). Пусть `W_i` — взвешенные победы, `n_ij` — суммарный вес сравнений пары, `α` — prior (псевдо-победы/поражения против «среднего» достижения с силой 0):

```text
θ_i ← (W_i + α) / ( Σ_j n_ij/(θ_i+θ_j) + α/(θ_i+1) )
```

После каждой итерации:

```text
θ_i ← θ_i / exp(mean_j ln θ_j)
```

Остановка — `max |ln θ_i^(new) − ln θ_i^(old)| < 1e-9` или 500 итераций. Prior `α=0.5` делает оценку конечной для изолированных достижений и стабилизирует редкие пары. Достижение без сравнений получает `s=0` (средний уровень).

Реализация — чистый Python без numpy/scipy: [`app/services/bradley_terry.py`](../app/services/bradley_terry.py).

## 4. Рейтинг и место

Сила `s` переводится в Elo-подобную шкалу:

```text
bt_rating = 1000 + 400 * s / ln(10)
```

- `1000` — средний уровень;
- `+400` — примерно десятикратное превосходство в шансах быть сложнее;
- `bt_strength` хранится отдельно (сырой логит) и используется для ранжирования;
- `bt_comparisons` — число попарных сравнений достижения (для оценки надёжности).

Место (`rank`) считается по `bt_strength desc`, затем `average_position asc`, `rank_order asc`, `id asc`. Пока BT ещё не пересчитан, используется старая средняя позиция как fallback. Порог «2 оценки» для попадания в глобальный рейтинг (миграция 022): до него достижение собирает данные, но не показывается в лидерборде.

## 5. Конвейер

```text
submit_evaluation / модерация / принятие жалобы
        │
        ▼
app/services/bt_recompute.py  (service role: все evaluations + published achievements)
        │  build_comparisons → fit_bradley_terry
        ▼
RPC public.apply_bt_ratings(jsonb)  (security definer)
        │  update bt_strength/bt_rating/bt_comparisons
        ▼
recompute_ranks_internal()  (rank по BT)
```

- Пересчёт best-effort: ошибка логируется и не ломает оценку/модерацию.
- Запись атомарна, параллельные применения сериализуются advisory-lock.
- `bt_*` защищены guard-триггером от прямого REST-обновления; RPC доступна только `service_role`.
- Ручной пересчёт: `python scripts/recompute_bt.py` (нужны `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`).

## 6. Эксперимент

`scripts/bt_experiment.py` генерирует достижения с известными силами, симулирует попарные сравнения по модели и проверяет восстановление шкалы; bootstrap пересэмплирует сравнения и показывает устойчивость.

Запуск:

```bash
python scripts/bt_experiment.py --items 40 --games 20 --bootstrap 10 --seed 42
```

Результат на синтетике (40 достижений, 20 игр на пару, 15 600 сравнений):

| Метрика | Значение |
|---|---|
| Spearman с истиной | **0.9908** |
| Kendall с истиной | **0.9333** |
| Brier score | **0.193** |
| Bootstrap Spearman (среднее) | **0.9910** |
| Bootstrap Spearman (минимум) | **0.9869** |
| Пересечение top-10 при bootstrap | **0.93** |

Это проверка алгоритма на данных, точно соответствующих модели. Реальные пользовательские шкалы зависимы и неоднородны, поэтому на живых данных метрики будут ниже; для отчётности нужно прогнать эксперимент на собранных оценках (см. ограничения).

## 7. Ограничения и дальнейшая работа

- **Зависимость наблюдений.** Все пары одной шкалы — одно упорядочение; весовое нормирование снижает, но не устраняет переоценку уверенности. Строже — Plackett–Luce / rank-ordered logit по полным рангам.
- **Связность графа.** Регуляризация даёт конечные силы даже для изолированных достижений, но их рейтинг — это prior, а не данные. Для интерпретации полезно показывать `bt_comparisons`.
- **Динамика.** При каждой новой оценке модель пересчитывается целиком (O(N·iter)); для роста данных нужен батчевый пересчёт/материализация и, возможно, онлайн-обновления.
- **Неопределённость.** Сейчас нет доверительных интервалов; bootstrap в эксперименте — первый шаг. В продакшене можно считать SE по гессиану или бутстрапу на батче.
- **Минимум оценок.** Порог 2 оценки — продуктовая эвристика, не свойство BT; её можно отвязать от ранжирования, показывая «предварительный» рейтинг.
